# Установка pulsar-brain

Документ описывает два пути: быстрый локальный стенд без Supervisor и установку на Home Assistant
OS / Supervised. Требования и архитектура — [README.md](../README.md), контракты —
[contracts.md](contracts.md).

## 0. Что понадобится

| Компонент | Требование |
|---|---|
| Колонка | Яндекс Станция с прошивкой pulsar (целевая — Лайт 2, `plum`, pulsar v0.5.3), ESPHome API :6053, Noise PSK |
| Home Assistant | HAOS или Supervised (аддоны требуют Supervisor), HA >= 2025.x, arch `aarch64`/`amd64` |
| STT | Wyoming Whisper (аддон `core-whisper` или внешний сервер), обычно :10300 |
| TTS | Wyoming Piper (аддон `core-piper` или внешний сервер), обычно :10200 |
| Сеть | Колонка должна открывать `internal_url` HA, чтобы скачать WAV ответа |
| Dev-стенд | Docker + compose v2, Python 3.12+ для `dev/.venv` |

Node.js на хосте не нужен: Node 22 и зависимости находятся внутри образа аддона.

## 1. Dev-стенд (без HAOS)

Стенд поднимает HA Core (порт 8124), Whisper (10300), Piper (10200) и аддон (8097). Supervisor нет,
поэтому ingress, `SUPERVISOR_TOKEN` и watchdog здесь не проверяются.

```sh
cd dev
docker compose up -d ha whisper piper
cd ..
dev/.venv/bin/python dev/bootstrap-ha.py
dev/check.sh
```

Ожидаемо:

- `bootstrap-ha.py` завершился без ошибок, созданы `dev/ha-token.txt`, `dev/state.json`, `dev/.env`;
- `dev/check.sh` печатает `Итог: OK=… FAIL=0 SKIP=…` и `Стенд в порядке.`, exit 0;
- HA открывается на <http://127.0.0.1:8124/> (логин `dev`, пароль `devpass`).

Если `dev/.venv` ещё нет, создай его по [dev/README.md](../dev/README.md) (нужен `aiohttp` для
`bootstrap-ha.py`). Первая загрузка моделей Whisper/Piper занимает 1–2 минуты.

Установка аддона и интеграции на стенд:

```sh
scripts/install-local.sh
```

Скрипт идемпотентен: собирает `pulsar-brain-addon:local`, пересоздаёт контейнер
`pulsar-brain-addon` в сети стенда, ждёт `/health`, копирует интеграцию в
`dev/ha-config/custom_components/` и перезапускает HA.

Ожидаемо:

- `docker build` завершился успешно;
- в выводе есть `/health: {"status":"ok",...}`;
- `UI (dev): http://127.0.0.1:8097/`;
- в `dev/ha-config/custom_components/pulsar_brain/` появились файлы интеграции.

Дальше добавь интеграцию: **Настройки → Устройства и службы → Добавить интеграцию → Pulsar Brain**,
адрес `pulsar-brain-addon`, порт `8097`, bridge token (см. §4), ESPHome-устройство — mock-сателлит
или колонка.

Если стенд не поднят, `install-local.sh` завершится ошибкой с инструкцией — это нормально, сначала
выполни шаги выше.

## 2. Установка аддона на HAOS / Supervised

### 2.1. Подготовка Home Assistant

1. Установи и запусти аддоны **Whisper** и **Piper** (официальный репозиторий) или подготовь
   внешние Wyoming-серверы. Запомни их хосты и порты.
2. Убедись, что колонка уже добавлена в HA как ESPHome-устройство и доступна. PSK хранится в
   config entry интеграции ESPHome.
3. Проверь `internal_url` HA: **Настройки → Система → Сеть**. Адрес должен быть доступен с колонки —
   иначе она не скачает WAV ответа.

### 2.2. Вариант A: установка из репозитория аддонов

1. **Настройки → Аддоны → Магазин** (в новых версиях — **Приложения**) → ⋮ → **Репозитории**.
2. Добавь URL репозитория, в корне которого лежит [repository.yaml](../repository.yaml):
   `https://github.com/Thedamem/pulsar-brain` или адрес локального git-сервера с этим
   репозиторием (репозиторий должен быть доступен Supervisor'у по сети).
3. Найди **Pulsar Brain** → **Установить** → **Запустить**.
4. Supervisor соберёт образ из `addon/Dockerfile` на устройстве. Первая сборка занимает несколько
   минут и требует сети (скачиваются npm-пакеты).

### 2.3. Вариант B: локальный аддон (работает сейчас)

Скопируй каталог `addon/` на HAOS в `/addons/pulsar_brain` (Samba-аддон или SSH):

```sh
ssh root@homeassistant 'mkdir -p /addons/pulsar_brain'
scp -r addon/. root@homeassistant:/addons/pulsar_brain/
```

В UI: **Настройки → Аддоны → Магазин** → ⋮ → **Перезагрузить** (Reload). В списке появится
локальный аддон **Pulsar Brain** → **Установить** → **Запустить**.

Проверка сборки:

```sh
ha apps info pulsar_brain      # в старых версиях CLI: ha addons info pulsar_brain
ha apps logs pulsar_brain      # журнал сборки и запуска
```

Ожидаемо: состояние `started`, в логах нет ошибок `npm ci`/`tsc`, страница аддона показывает
кнопку **Open Web UI**.

Если сборка падает, смотри §7 «Сборка аддона падает».

### 2.4. Первый запуск

1. Открой UI аддона: страница аддона → **Open Web UI** (ingress). За ingress Supervisor уже
   аутентифицировал пользователя, токен вводить не нужно.
2. При старте аддон объявляет себя Home Assistant через Supervisor discovery — в HA появится
   обнаруженная интеграция **Pulsar Brain** (см. §3.2).
3. **Bridge token** вводить не требуется. Он нужен только для ручной настройки интеграции, если
   автообнаружение отключено, и показан в **Настройки → Токен моста** аддона. Это секрет:
   не коммить, не вставляй в чаты и не печатай целиком в логи.

Ожидаемо: UI открывается, **Обзор** показывает статус сервиса и здоровье Whisper/Piper/HA,
в разделе **Станция** — «не привязана» до шага §3.3.

## 3. Интеграция и привязка станции

Интеграция ставится отдельно от аддона (папка `custom_components/pulsar_brain` в `/config`), но
настраивается автоматически: аддон передаёт Home Assistant свой hostname, порт и токен, а станцию
выбирают в админке аддона. Вводить адреса и токены в HA не нужно.

### 3.1. Установка файлов интеграции

- **HACS / Marketplace:** HACS → ⋮ → **Custom repositories** →
  `https://github.com/Thedamem/pulsar-brain` → category **Integration** → установить.
- **Вручную из релиза:**

  ```sh
  cd /config
  wget -O /tmp/pulsar_brain.zip \
    https://github.com/Thedamem/pulsar-brain/releases/download/v0.2.0/pulsar_brain.zip
  unzip -o /tmp/pulsar_brain.zip -d /config
  ```

- **С рабочей машины** (Samba или SSH):

  ```sh
  ssh root@homeassistant 'mkdir -p /config/custom_components'
  scp -r custom_components/pulsar_brain root@homeassistant:/config/custom_components/
  ```

### 3.2. Автонастройка

**Настройки → Система → Перезапустить** (или `ha core restart`). После перезапуска HA покажет
обнаруженную интеграцию **Pulsar Brain** — нажми **Настроить**. Полей нет: hostname, порт и bridge
token пришли от аддона через Supervisor discovery.

Если автообнаружение не сработало (интеграцию поставили позже аддона и сообщение о discovery
потерялось), перезапусти HA ещё раз или добавь интеграцию вручную:
**Настройки → Устройства и службы → Добавить интеграцию → Pulsar Brain** → hostname аддона
(`ha --raw-json apps info pulsar_brain | grep -o '"hostname": *"[^"]*"'`), порт `8097`, bridge token
из UI аддона. Станция всё равно выбирается в аддоне.

Ожидаемо: config entry создан, сущности появились, `binary_sensor.connection` = `off` до привязки
станции.

### 3.3. Привязка станции (в аддоне)

1. UI аддона → **Станция**. Список **Устройства ESPHome из Home Assistant** приходит от интеграции
   (имя, host:port, MAC).
2. Выбери колонку с прошивкой pulsar → **Привязать**. Аддон сохраняет привязку и вызывает HA-сервис
   `pulsar_brain.set_station`; интеграция берёт host/port/PSK из записи **ESPHome** в HA (PSK не
   покидает Home Assistant) и подключается к колонке.
3. Если колонки нет в списке, раскрой **Другой адрес**: имя, host, port (обычно `6053`) и Noise PSK
   из записи ESPHome → **Привязать вручную**.
4. Отвязать — кнопка **Отвязать** в том же разделе (мост освободит голосовой слот).

Ожидаемо: `binary_sensor.connection` = `on`, `sensor.station` показывает имя колонки, в UI аддона
**Обзор → Мост** — «Подключён».

### 3.4. Сущности и сервисы

| Сущность | Что показывает |
|---|---|
| `binary_sensor.connection` | связь моста с аддоном |
| `sensor.station` | привязанная колонка (нет — «не привязана») |
| `sensor.last_transcript` | последняя распознанная фраза |
| `sensor.last_response` | последний ответ ассистента |
| `select.provider` | выбранный провайдер |
| `switch.enabled` | подписка моста на voice assistant |
| `button.restart_bridge` | перезапуск моста |

Сервисы: `pulsar_brain.ask` (текстовая команда), `pulsar_brain.announce` (озвучка текста),
`pulsar_brain.set_station` (вызывается аддоном; можно использовать в автоматизациях).

### 3.5. Проверка

1. `binary_sensor.connection` = `on`, `sensor.station` — имя колонки.
2. В UI аддона **Обзор** — зелёные Whisper, Piper, HA, провайдер `mock`.
3. Скажи «Алиса, включи свет». Ожидаемо: колонка отвечает голосом, `light.kitchen` (или твой свет)
   включается, в **Истории** появляется run.
4. Текстовая проверка без колонки: **Инструменты разработчика → Действия** →

   ```yaml
   action: pulsar_brain.ask
   data:
     text: "включи свет"
   ```

   Ожидаемо: ответ в `response`, действие выполнено.
5. Follow-up: после ответа скажи «а теперь выключи» без «Алисы». Ожидаемо: новый run без wake word.

## 4. Настройка после установки

- **Провайдеры.** UI → **Провайдеры** → выбрать, заполнить, **Проверить**, **Сохранить**. Без
  ключей оставь `mock`: ответы детерминированные, инструменты работают.
- **Станция.** UI → **Станция**: список берётся из интеграции ESPHome; привязка и отвязка — там же.
- **STT/TTS.** UI → **Ассистент**: хост/порт Whisper и Piper, язык, голос, режим озвучки. В HAOS
  это аддоны `core-whisper:10300` и `core-piper:10200`.
- **MCP.** UI → **MCP** → добавить сервер (HTTP/SSE/stdio), **Проверить**, сохранить. Для stdio
  бинарник должен быть внутри образа аддона.
- **Планировщик.** Разовые таймеры и отложенные действия — в SQLite; повторяющиеся — нативные
  automation HA.
- **Промпт и алиасы.** UI → **Ассистент** (промпт, язык, follow-up, barge-in) и **Настройки**
  (алиасы, лог, токены).

## 5. Обновление

1. Скопируй новые файлы аддона в `/addons/pulsar_brain` (локальная установка) или обнови из
   репозитория.
2. UI аддона → ⋮ → **Пересобрать** (Rebuild) → **Перезапустить**. Данные в `/data` сохраняются.
3. Обнови интеграцию: скопируй `custom_components/pulsar_brain` заново и перезапусти HA.
4. Прогони проверки: `scripts/check-all.sh` (на машине разработчика).

## 6. Удаление

1. Удали интеграцию: **Настройки → Устройства и службы → Pulsar Brain → Удалить**.
2. Удали аддон: страница аддона → **Удалить**. Данные `/data` удаляются вместе с аддоном; для
   сохранения сделай backup (аддон помечен `backup: cold`).
3. Удали `/config/custom_components/pulsar_brain` и перезапусти HA.

## 7. Типовые ошибки

### 7.1. Интеграция не появляется в списке

- Проверь путь: `/config/custom_components/pulsar_brain/manifest.json` должен существовать.
- Проверь, что скопирован весь каталог, а не только `manifest.json`.
- Перезапусти HA и посмотри **Настройки → Система → Логи** (`home-assistant.log`) на ошибки
  `pulsar_brain`.
- Убедись, что версия HA >= 2025.x и Python-зависимости интеграции доступны.

### 7.2. Аддон недоступен (`Connection refused`, timeout)

- Аддон не запущен: страница аддона → **Запустить**, проверь `ha apps logs pulsar_brain`.
- Неверный hostname: для локального аддона `local-pulsar-brain`, для репозитория —
  `<id>-pulsar-brain`; проверь командой из §3.4.
- Порт должен быть `8097`; наружу он не публикуется, интеграция ходит по внутренней сети
  Supervisor.
- Watchdog перезапускает аддон, если `/health` не отвечает; смотри логи.

### 7.3. `401 Unauthorized` / токен не подошёл

- Скопируй bridge token заново: в нём не должно быть пробелов и перевода строки.
- Токен мог перегенерироваться: удали `/data/bridge-token.json`, перезапусти аддон и обнови
  интеграцию. Старый токен после этого недействителен.
- Для прямого доступа к UI нужен `PULSAR_BRAIN_UI_TOKEN`, а не bridge token (за ingress токен не
  нужен).

### 7.4. Нет PSK / ESPHome не подключается

- PSK колонки хранится в config entry интеграции ESPHome того HA, который её изначально добавил.
  Если колонка добавлялась в другой HA, PSK там и недоступен — добавь устройство в этот HA или
  используй mock-сателлит.
- Проверь, что колонка в сети, ESPHome API :6053 открыт и прошивка pulsar отвечает.
- Без PSK живое подключение невозможно; mock-сателлит работает без шифрования.

### 7.5. Whisper или Piper не подняты

- Установи и запусти `core-whisper` / `core-piper` (или внешние Wyoming-серверы).
- Проверь хосты/порты в UI → **Ассистент**: Whisper :10300, Piper :10200.
- В dev: `docker compose ps`, `dev/check.sh`, `docker compose logs whisper piper`.
- Кнопка предпросмотра TTS должна отдавать WAV; если нет — смотри лог аддона.

### 7.6. Порт 8097 занят (dev)

```sh
ss -ltnp | grep 8097
docker ps --format '{{.Names}}\t{{.Ports}}' | grep 8097
```

Останови конфликтующий контейнер/процесс и повтори `scripts/install-local.sh`. Скрипт сам удаляет
старый контейнер `pulsar-brain-addon`, но не трогает чужие процессы. Если запущен compose-аддон
стенда (`pulsar-dev-addon-1`), останови его: `docker compose -f dev/docker-compose.yml stop addon` —
`install-local.sh` запускает собственный контейнер на том же порту.

### 7.7. Ingress отдаёт 502 / UI не открывается

- Аддон не прошёл `/health`: смотри `ha apps logs pulsar_brain`.
- Проверь, что контейнер не падает на старте (нехватка памяти, битый `/data/config.json`).
- Watchdog и перезапуск: страница аддона → **Перезапустить**.
- В dev проверь `curl http://127.0.0.1:8097/health`.

### 7.8. Нет звука ответа

- Колонка не смогла скачать WAV: проверь `internal_url` HA и доступность адреса с колонки.
- Piper не синтезирует: предпросмотр TTS в UI, логи аддона.
- Для Gemini Live ответ сначала генерируется целиком — это задержка, а не отсутствие звука.
- Проверь громкость media_player колонки.

### 7.9. Планировщик срабатывает не вовремя

- Время считается в часовом поясе контейнера. Проверь `date` внутри контейнера аддона и сравни с
  HA; при расхождении задай TZ.
- Повторяющиеся правила — это automation HA; проверь их в **Настройки → Автоматизации**.

### 7.10. Сборка аддона падает на HAOS

- Нет сети до npm registry: Supervisor не скачает зависимости.
- Не хватает диска/памяти: смотри логи Supervisor.
- Неподдерживаемая архитектура: в `config.yaml` только `aarch64` и `amd64`.
- Ошибка `tsc`: код аддона не компилируется; на машине разработчика запусти
  `scripts/check-all.sh`.

### 7.11. UI просит токен

- За ingress введи любое непустое значение (например, `ingress`) — API уже авторизован Supervisor.
- Для прямого доступа задай `PULSAR_BRAIN_UI_TOKEN` и используй его.
- Bridge token тоже принимается API, но не предназначен для людей.

### 7.12. Отвечает mock вместо провайдера

- В dev задан `PULSAR_BRAIN_MOCK=1` — он принудительно включает `mock`.
- На HAOS проверь выбранного провайдера в UI → **Провайдеры**; ключ должен пройти **Проверить**.

## 8. Чек-лист приёмки

- [ ] `dev/check.sh` (dev) или `ha apps info pulsar_brain` (HAOS) — без ошибок.
- [ ] `/health` аддона отвечает `{"status":"ok",...}`.
- [ ] UI открывается через ingress; bridge token скопирован.
- [ ] Интеграция добавлена, `binary_sensor.connection` = `on`.
- [ ] `pulsar_brain.ask` возвращает ответ.
- [ ] Голосовой сценарий: свет, несколько действий, таймер, отложенное действие, follow-up,
      barge-in.
- [ ] Whisper и Piper зелёные в **Обзоре**.
- [ ] В логах нет секретов и необработанных исключений.
